## 1. 商业模型核心

### ✅ verified 的事实

| 事实 | 来源 |
|---|---|
| 会员价 ¥2000 | 36kr 创始人专访 |
| 服务承诺：3 年内未领证结婚可全额退款 | 36kr + c114 |
| 退款承诺基线：深圳约 150 对夫妻样本，70% 在 3 年内结婚 | 36kr |

### 商业逻辑

```
¥2000 会员费
  ├─ 30% ≈ ¥600  → AI 服务成本（含 DeepSeek / 豆包 / 环信 / 珊瑚）
  ├─ 30% ≈ ¥600  → 履约保障基金（应对 30% 退款用户）
  ├─ 20% ≈ ¥400  → 获客成本（CAC）
  ├─ 15% ≈ ¥300  → 运营成本（人力 + 客服 + 审核）
  └─ 5%  ≈ ¥100  → 净利润
```

> 若用户群匹配深圳样本，70% 用户在 3 年内结婚 → 履约基金压力可控。

## 2. 风险分析

### 高风险点

| 风险 | 影响 | 缓解 |
|---|---|---|
| **退款承诺的法律性质** | 若被认定为「附条件赠与」或「预付费消费」，可能引发集体诉讼 | 明确为「服务承诺」非「保证」；条款需公司法务审核 |
| **退款率失控** | 若匹配质量差，30% 履约基金被击穿 | 风控：资料评分门槛 + 1v1 强制撮合 |
| **IAP 30% 抽成** | Apple 抽走 ¥600/单，履约基金不足 | App 端定价补足：¥2200 vs 小程序 ¥2000 |
| **监管对「保结婚」承诺的态度** | 工商部门可能认定为「虚假承诺」| 改为「保推荐」+「保服务」措辞，避免「保结果」|

### 中风险点

| 风险 | 影响 |
|---|---|
| 种子用户冷启动 | 婚恋类最难的是首批 1000 个高质量女性 |
| 资料评分模型歧视争议 | MBTI / 学历等筛选可能被指「学历歧视」 |
| 退款用户再次入会意愿低 | 退款后流失 |

### 低风险点

| 风险 | 影响 |
|---|---|
| AI 红娘成本上升 | DeepSeek 涨价 20% 影响小 |
| 环信 SLA 下降 | 已准备 local fallback |

## 3. 复刻方案的商业模式建议

### MVP 阶段（M1-M2）

**只做**：

| 收入项 | 价格 | 备注 |
|---|---|---|
| 月度会员 | ¥68 | 体验 AI 红娘 + 无限匹配 |
| 季度会员 | ¥188 | 同月度 ×3 + 1 次人工红娘 |
| AI 军师单次 | ¥19.9 | 单次关系诊断 |

**不做**：
- ¥2000 保结婚会员（M3 之后）
- 退款承诺（M3 之后）
- 线下活动（现金流不足以支撑）

### 商业化阶段（M3+）

引入 ¥2000「保推荐会员」（**不是**「保结婚」）：

- 履约承诺：3 年内推荐 ≥ 10 位匹配对象 + ≥ 3 次人工红娘
- **不承诺**结婚结果
- 退款条件：未达承诺可申请部分退款

> **关键差异**：从「保结果」改为「保服务」，规避法律风险。

## 4. 退款履约的工程方案

```sql
-- 退款履约表
CREATE TABLE refund_obligations (
  id              BIGSERIAL PRIMARY KEY,
  user_id         BIGINT,
  order_id        BIGINT,
  sku_id          TEXT,
  amount_cents    INT,
  expires_at      TIMESTAMPTZ,    -- 3 年后
  status          SMALLINT,        -- 1active 2fulfilled 3refunded
  matched_count   INT,
  human_match_count INT
);

-- 每年 1 月批量检查到期用户
-- 自动发放会员期顺延券（不退现金）或进人工队列
```

**核心逻辑**：
- 用户在 3 年内结婚 → 自动核销履约义务（需用户提供结婚证）
- 用户在 3 年内未结婚 → 自动发放补偿券，不退现金（避免被薅）
- 极端情况：用户坚持退现金 → 进人工队列，单笔处理
