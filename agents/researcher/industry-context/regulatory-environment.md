# 监管环境 · 婚介 + AI 双重监管

> 中国法律环境下，婚恋类目 + AI 服务双重监管的要求梳理。
> 本文档为**合规层**输入，配合 ⚖️ 合规法务 Agent 工作。

---

## 1. 监管框架总览

良配复刻版需同时满足 **三层监管**：

```
┌─────────────────────────────────────┐
│  Layer 1: 婚恋类目                  │
│  └─ ICP 备案 + 婚介资质（经营性）  │
├─────────────────────────────────────┤
│  Layer 2: 算法推荐                  │
│  └─ 算法备案（《算法推荐管理规定》）│
├─────────────────────────────────────┤
│  Layer 3: AI 生成内容              │
│  └─ 深度合成备案 + 大模型备案      │
└─────────────────────────────────────┘
```

> **三层全部完成** 才能合法上线。

---

## 2. Layer 1 · 婚介类目

### 2.1 ICP 备案

| 维度 | 要求 |
|---|---|
| 依据 | 《互联网信息服务管理办法》 |
| 受理部门 | 工信部（小程序在腾讯 / 阿里后台）|
| 周期 | 7-20 个工作日 |
| 必备材料 | 营业执照、域名证书、身份证、法人手机号 |
| 难度 | ⭐ 简单 |

### 2.2 婚介资质（经营性）

| 维度 | 要求 |
|---|---|
| 依据 | 《婚姻介绍服务管理办法》（民政部） |
| 受理部门 | 当地民政局 |
| 周期 | 30-60 个工作日（**最长**）|
| 必备材料 | 公司营业执照、经营场所证明、红娘资质证书 |
| 难度 | ⭐⭐⭐ 中等 |

> **关键**：婚介资质要求「经营场所」——一人复刻团队常以「虚拟办公」或「挂靠主体」方式解决。

### 2.3 微信小程序类目

| 维度 | 要求 |
|---|---|
| 服务类目 | 生活服务 > 婚恋服务 |
| 必备资质 | ICP 备案 + 婚介资质 + 微信商户号 |
| 审核周期 | 1-7 个工作日 |
| 难度 | ⭐⭐ 中等（微信可能要求补充材料）|

## 3. Layer 2 · 算法推荐

### 3.1 算法备案

| 维度 | 要求 |
|---|---|
| 依据 | 《互联网信息服务算法推荐管理规定》（2022-03-01 施行） |
| 受理部门 | 国家网信办 + 地方网信办 |
| 周期 | 30-90 个工作日 |
| 必备材料 | 算法说明文档、安全评估报告、用户协议、应急处置机制 |
| 难度 | ⭐⭐⭐⭐ 较高 |

### 3.2 算法备案范围

> 以下算法**均需备案**：
> - 个性化推送（匹配推荐）
> - 排序精选（候选排序）
> - 检索过滤（搜索筛选）
> - 调度决策（资源分配）
> - 生成合成（AI 内容生成） → 走 Layer 3

### 3.3 良配复刻版需备案的算法

| 算法 | 用途 | 备案项 |
|---|---|---|
| 匹配召回 | pgvector ANN | 个性化推送 |
| 匹配精排 | DeepSeek-V3 LLM | 排序精选 |
| 资料评分 | 规则 + LLM | 排序精选 |
| AI 红娘对话 | DeepSeek-V3 | 生成合成（Layer 3）|
| AI 分身问答 | DeepSeek-V3 + Embedding | 生成合成（Layer 3）|

## 4. Layer 3 · AI 生成内容

### 4.1 深度合成备案

| 维度 | 要求 |
|---|---|
| 依据 | 《互联网信息服务深度合成管理规定》（2023-01-10 施行） |
| 受理部门 | 国家网信办 |
| 周期 | 30-90 个工作日 |
| 必备材料 | 算法备案号 + 语料备案 + 模型说明 + 安全评估 |
| 难度 | ⭐⭐⭐⭐⭐ 高 |

### 4.2 大模型备案

| 维度 | 要求 |
|---|---|
| 依据 | 《生成式人工智能服务管理暂行办法》（2023-08-15 施行） |
| 受理部门 | 国家网信办 |
| 周期 | 30-90 个工作日 |
| 必备材料 | 模型来源 / 微调说明 / 训练语料 / 安全评估 / 语料方授权 |
| 难度 | ⭐⭐⭐⭐⭐ 高 |

### 4.3 良配复刻版的合规路径

> 由于使用 DeepSeek-V3 + Qwen 等第三方模型，**模型本身已由供应商备案**——复刻版只需做**应用层备案**（深度合成备案）。

| 备案项 | 内容 |
|---|---|
| 应用名称 | 良配（复刻版）|
| 模型来源 | DeepSeek-V3 API（已备案） + Qwen Embedding API |
| 应用场景 | AI 红娘对话 + AI 分身问答 |
| 数据来源 | 用户授权公开资料 + 用户授权问卷 + 红娘代聊样本 |
| 用户授权机制 | 单独的 AI 能力开通同意书 |
| 数据留存 | 用户可一键删除（个保法要求）|

## 5. 个保法 / 隐私合规

### 5.1 个保法核心要求

> 《个人信息保护法》（2021-11-01 施行）

| 要求 | 复刻版实现 |
|---|---|
| 知情同意 | 注册时明确告知 AI 能力用途 |
| 最小必要 | 仅收集评分所需字段 |
| 单独同意 | AI 红娘 / 分身需单独勾选 |
| 一键删除 | 用户设置页提供「清除 AI 数据」按钮 |
| 数据本地化 | 用户境内数据不出境 |

### 5.2 敏感个人信息

> 婚恋类涉及的**敏感个人信息**：
> - 身份证号（二要素）
> - 人脸图像（活体）
> - 真实住址
> - 婚史 / 健康状况 / 性取向

| 措施 | 实现 |
|---|---|
| 加密存储 | 身份证号 AES-256 |
| 单独表隔离 | `id_verifications` 表，独立权限 |
| 访问审计 | 所有敏感字段访问写日志 |

## 6. 退款承诺的法律风险

### 6.1 法律性质

> ¥2000 保结婚会员退款承诺的法律性质有争议：

| 性质 | 法律风险 |
|---|---|
| 服务承诺 | 低（属正常服务条款）|
| 保证承诺 | 中（可能被认定为虚假宣传）|
| 附条件赠与 | 高（撤销条件争议）|
| 预付费消费 | 中（消法 7 天无理由）|

### 6.2 合规建议

> 措辞上避免「保证」「承诺结婚」等绝对化用语，使用：
> - ✅ 「保推荐」——确保服务量
> - ✅ 「保服务」——确保服务质量
> - ❌ 「保结婚」——避免结果承诺

> 详见 `../liangpei-product/business-model.md` 复刻方案建议。

## 7. 监管时间线（建议）

| 时间 | 行动 |
|---|---|
| M0 第 1 周 | 启动 ICP 备案 + 微信商户号 |
| M0 第 1 周 | 启动婚介资质申请（最长）|
| M0 第 2 周 | 启动算法备案 |
| M0 第 2 周 | 启动深度合成备案 |
| M1-M2 | 等候备案结果（并行开发）|
| M3 之前 | 备案全部完成 |
| M3 上线 | 备案号写入用户协议 |

> **风险点**：若 M3 备案未完成，强行上线会被网信办约谈 / 下架。
