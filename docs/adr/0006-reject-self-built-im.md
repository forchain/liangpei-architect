# ADR-0006 · ❌ 拒绝自建 WebSocket IM

| 项 | 值 |
|---|---|
| 状态 | ✅ Accepted（拒绝方案） |
| 日期 | 2026-08-01 |
| 决策者 | @forchain |

---

## Context

评估 IM 方案时，认真考虑过自建 WebSocket + MongoDB 的方案。这份 ADR 是为了**正式记录拒绝原因**，避免未来被"省钱"诱惑而重启。

---

## Decision

**正式拒绝自建 IM 方案**。选用环信专业版（详见 ADR-003）。

---

## 拒绝原因

### 1. 开发周期不划算

| 工作项 | 工时 |
|---|---|
| WebSocket 网关（连接管理 / 心跳 / 鉴权）| 2 周 |
| 消息存储（分片 / 索引 / 归档）| 2 周 |
| 离线推送（APNs / FCM / 小程序模板）| 1 周 |
| 消息可靠投递（ACK + 重传 + 幂等）| 2 周 |
| 内容审核串联 | 1 周 |
| 监控告警 | 0.5 周 |
| **合计** | **8.5 周** |

而一人团队的 M1 总周期只有 4 周——根本放不下。

### 2. 消息丢失风险高

自建 IM 在以下场景几乎必然丢消息：

- 用户切后台被系统 kill（Android 尤其严重）
- WebSocket 断线重连（NAT 超时、运营商劫持）
- 多设备登录消息同步
- 消息已读状态同步

婚恋场景丢消息 = 用户流失。环信在 SLA 上承诺 P99 < 1s，自建几乎做不到。

### 3. 隐性成本

| 隐性成本 | 估算 |
|---|---|
| 服务器（WebSocket 长连接） | ¥500/月（DAU 1 万） |
| MongoDB 集群 | ¥300/月 |
| Redis（pub/sub） | ¥200/月 |
| 运维人力（事故响应）| 4 小时/周 |
| 一年事故损失（保守）| ¥5 万 |

一年总成本 ≈ ¥12 万，**远高于**环信专业版的 ¥0.6 万/年。

---

## Consequences

**正面**
- 节省 8.5 周开发时间
- 节省约 ¥11 万 / 年运维 + 事故成本
- 专业 SLA（P99 < 1s）

**负面**
- 锁定环信生态
- 月度成本随 DAU 增长（DAU 5 万时约 ¥1,500/月，仍可接受）

---

## Alternatives Considered

### 自建 + 用 SDK（双方）
- ❌ 复杂度更高，不解决核心问题

### 自建 + 用 SQLite + WebSocket
- ❌ 完全不严肃，婚恋场景不能用

---

## 触发重评估的条件

| 条件 | 行动 |
|---|---|
| DAU > 10 万 | 重评估成本（环信专业版可能涨到 ¥1 万/月） |
| 环信 SLA 持续不达标（3 个月） | 重新评估腾讯云 IM 或自建 |
| 出现自定义 IM 需求（如阅后即焚） | 评估用环信扩展 API 是否满足 |

---

## 经验教训

> **不要用工程师的"我能造"替代产品的"我需要"**。
> 自建 IM 是典型的"看似省钱实则昂贵"的陷阱——前期投入 2 个月 + 长期运维黑洞。
