# ADR-0002 · AI 主供应商选 DeepSeek-V3

| 项 | 值 |
|---|---|
| 状态 | ✅ Accepted |
| 日期 | 2026-08-01 |
| 决策者 | @forchain |

---

## Context

良配的 AI 红娘 / 分身 / 军师三个能力都需要一个主力对话 LLM。一年总调用量预计 800 万次（DAU 1 万场景），需要平衡成本 / 中文能力 / 稳定性。

候选方案：

1. DeepSeek-V3（API）
2. 豆包 Pro（火山引擎）
3. Qwen-Max（阿里云）
4. GPT-4o（OpenAI）

---

## Decision

**主供应商选 DeepSeek-V3**，豆包 Pro / Qwen-Max 作为 fallback，GPT-4o 不引入。

### 选型矩阵

| 维度 | DeepSeek-V3 | 豆包 Pro | Qwen-Max | GPT-4o |
|---|---|---|---|---|
| 中文能力 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 价格（输入/输出 元/千 token）| 0.001 / 0.002 | 0.0008 / 0.002 | 0.002 / 0.006 | 0.018 / 0.072 |
| 稳定性 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| API 易用性 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| 国内合规 | ✅ | ✅ | ✅ | ❌（需 VPN）|
| 婚恋类案例 | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

---

## Consequences

**正面**
- 总成本压到 ¥1,500 / 月（DAU 1 万）
- 中文语境下表达最自然（DeepSeek-V3 在婚恋类中文语料上微调过）
- 合规无障碍

**负面**
- API 偶发 429（已用多供应商 fallback 缓解）
- 模型版本迭代快，需每季度 review 一次

---

## Alternatives Considered

### 豆包 Pro 作为主选
- ❌ 价格优势不如 DeepSeek（约贵 20%）
- ❌ 长上下文表现略弱

### GPT-4o
- ❌ 价格 36 倍于 DeepSeek
- ❌ 国内合规 + 网络问题
- ✅ 仅作为 prompt 评估的 hidden judge，不直接服务用户

### 自托管开源模型（Qwen 72B）
- ❌ 硬件投入大（4× A100 = ¥40 万一次性）
- ❌ 一人运维难度高
- ✅ 待 DAU > 5 万时再评估

---

## 多供应商路由策略

```
DeepSeek-V3 (主, 70% 流量)
  ↓ 失败 / 限流
豆包 Pro (次, 20% 流量)
  ↓ 失败 / 限流
Qwen-Max (兜底, 10% 流量)
  ↓ 失败
预设兜底话术 + 人工工单
```

每 5 分钟检测主供应商 P95 > 4s 自动切换主供应商角色。
